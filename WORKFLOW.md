# Team Workflow

## Coding Standards

* Use clear and meaningful variable and function names.
* Use consistent indentation.
* Keep functions simple and focused.
* Test code before creating a Pull Request.
* Use clear commit messages.

## Branch Strategy

* The `main` branch contains the stable version of the project.
* Each feature is developed in a separate feature branch.
* Feature changes are not made directly on `main`.

## Pull Requests

* Each completed feature must be submitted through a Pull Request.
* Another team member reviews the Pull Request.
* Review comments must be addressed before merging.
* A Pull Request must be approved before it is merged into `main`.

## Definition of Done

A task is considered complete when:

* The feature has been implemented.
* The feature has been tested.
* The code has been reviewed.
* Review comments have been addressed.
* The Pull Request has been approved.
* The Pull Request has been merged into `main`.
